# 苍穹签到系统

基于人脸识别的课堂签到应用，使用电脑自带摄像头即可完成学生注册与实时签到，数据全部保存在本地，无需联网、无需服务器。

## 功能一览

| 模块 | 说明 |
|------|------|
| 学生管理 | 增删改查学生（姓名、学号、班级），查看人脸注册状态 |
| 人脸注册 | 调用摄像头拍摄学生照片，自动提取人脸特征存库（建议每人 2–3 张） |
| 课程管理 | 创建课程并关联班级 |
| 实时签到 | 摄像头实时识别，识别成功自动标记出勤，同人同场次防重复 |
| 防代签 | 静默活体 + 随机动作挑战（张一次 / 张两次嘴）+ 一次性令牌；照片和预录视频都过不去 |
| 签到记录 | 按课程/日期查看出勤与缺勤名单，导出 CSV（Excel 可打开） |

## 技术栈

- 前端：原生 HTML / CSS / JavaScript（浏览器运行）
- 后端：Python FastAPI
- 人脸识别：InsightFace（SCRFD 检测 + ArcFace 512 维特征）+ onnxruntime，CPU 实时推理
- 活体检测：MiniFASNetV2 静默活体模型，拦截照片/屏幕代签
- 存储：SQLite 本地数据库

## 环境要求

- Python **3.11 或更高版本**（安装时务必勾选 “Add Python to PATH”）
  - 下载地址：<https://www.python.org/downloads/>
- Windows 或 macOS 电脑，带摄像头
- 首次运行需要联网（用于安装依赖），之后可完全离线使用

## 模型文件（克隆后必读）

本仓库**不包含** `models/*.onnx`：4 个模型合计 189MB，其中 `w600k_r50.onnx` 单文件 167MB，
超过 GitHub 单文件 100MB 的硬限制。克隆之后请按 **[`models/README.md`](models/README.md)**
把 4 个 ONNX 文件放进 `models/`，否则服务启动后无法识别人脸。

判断是否放对了：访问 `/api/health`，`model_ready`、`liveness_ready`、`landmark_ready`
三个字段都应为 `true`。

## 快速开始

### Windows

双击 `start.bat`。首次运行会自动创建环境并安装依赖（约几分钟），随后自动打开浏览器进入系统。

### macOS

双击 `start.command`（若提示无权限，在终端执行一次 `chmod +x start.command`）。
首次运行自动安装依赖，随后自动打开浏览器。

> 启动后终端会打印两个地址：本机用的 <http://127.0.0.1:8000>，以及**手机用的** `http://<你的局域网IP>:8000`。

## 手机访问（同一个 WiFi）

启动后，用手机浏览器打开终端里打印的那个「手机访问」地址即可，例如 `http://172.28.189.66:8000`。

**手机第一次打不开，99% 是 Windows 防火墙拦了。** 右键「以管理员身份运行」`allow-phone-access.bat`，放行一次即可（脚本会自动把你电脑的地址打印出来）。

几点说明：

- 手机和电脑必须连**同一个 WiFi**。
- 如果学校/单位 WiFi 开启了「**客户端隔离**」（同一网络下设备互相看不见），手机仍然连不上。这种情况需要改用「隧道」方式，让电脑获得一个公网网址——需要时找 WorkBuddy 配置。
- 手机浏览器打开的是 **http 页面**，受浏览器安全策略限制，**手机自己不能调用摄像头**。这不影响使用：人脸识别和摄像头都在电脑上，手机是用来查看签到进度、查记录、管理学生的。
- 手机上界面会自动变成单列布局，「签到名单」会排在摄像头画面**前面**，方便直接看谁没到。

## 公网访问（手机也能刷脸签到）

浏览器规定：**只有 HTTPS 页面才能调用摄像头**。局域网是 http，所以手机上想签到必须走 HTTPS —— 也就是公网。

双击 **`start-public.bat`**，它会做两件事：

1. 在本机启动服务（`http://127.0.0.1:8000`，电脑照常用）；
2. 用 SSH 开一条加密隧道（走 serveo.net，**不用下载任何工具、不用注册账号**），
   窗口里会打印一个 `https://……` 的公网地址。

把那个 `https://` 地址用手机浏览器打开即可 —— 手机摄像头能正常用了。

> 现在是**随机网址**，每次启动会变；窗口里会显示，复制或扫码都行（serveo 还会直接给出二维码）。
> 想要一个**固定网址**（学生可以存书签）需要注册一个免费账号绑定 SSH 密钥，需要时找 WorkBuddy 配置。

**保持那个窗口开着**，关掉它公网地址就失效了。

### 手机能做什么、不能做什么

手机端被裁剪成「**选课程 → 刷脸签到**」—— 界面上只有「实时签到」这一个页面，
除了刚刷脸的那个人，看不到任何其他学生的信息。

| | 电脑（本机浏览器） | 手机（局域网 / 公网） |
|---|---|---|
| 选择课程 | ✅ | ✅ |
| 实时签到（刷脸） | ✅ | ✅ |
| 查看签到记录 | ✅ | ❌ 页面不可见，接口返回 403 |
| 看到「谁到了 / 谁没到」的完整名单 | ✅ | ❌ 整块不显示 |
| 看到刚刷脸那个人的信息 | ✅ | ✅ 只有这一条 |
| 学生管理（增删改） | ✅ | ❌ 页面不可见 |
| 课程管理 | ✅ | ❌ 页面不可见 |
| 注册人脸 / 删除人脸 | ✅ | ❌ 按钮不显示，接口返回 403 |
| 删除学生 | ✅ | ❌ 同上 |
| 清空签到记录 | ✅ | ❌ 按钮不显示，接口返回 403 |

手机上刷脸成功后，只会出现一张卡片：

```
✓  郭哥
   2022140101 · 签到成功 23:40:12
```

看不到其他任何学生。如果这个人本次已经签过到，卡片会提示「已经签到过了」。

这不是界面上藏按钮那么简单：**后端会真的拦截**。人脸写操作、以及签到记录的查询与清空，
只接受「本机浏览器直连」的请求；手机走局域网时来源不是回环地址，走隧道时一定带代理头，
两种都被拒绝（返回 403）。手机端连「全班名单」都不会去请求——名单面板隐藏的同时，
前端也不会调用拉取名单的接口。

### 关于速度

公网路径要绕到隧道服务器再回来，实测单次请求约 **1.6 秒**（局域网是 0.003 秒）。
加上本机人脸识别的耗时，手机签到一帧大约 2~4 秒 —— 能用，学生站定一下即可。
**追求最流畅的体验，就在电脑上签到。**

### 关于隐私

- 人脸特征、学生名单、签到记录**全部存在这台电脑的 `data/attendance.db` 里**，不会上传到任何服务器。
- **系统不保存人脸照片。** 学生注册时拍的照片只在**内存里**过一遍，提取成一串 512 个数字的
  「特征向量」后存进数据库，照片本身当场就被丢弃了。特征向量不能直接还原成照片。
- **临时痕迹会自动清掉。** 签到过程中记住的「最近识别到了谁」只放在**内存**里、不落盘，
  默认 **2 小时**后自动消失；唯一可能留下人脸画面的调试功能默认关闭，且开启了也会每 2 小时清空一次。
  在「实时签到」页右下角能看到当前缓存状态，也可以随时点「立即清空」。
- **注意区分**：签到记录是**长期保存**的教学证据，不会被上面那套清理影响 ——
  自动清理的只是临时的识别痕迹，不是签到记录。
- 走公网时，画面数据会**经过隧道服务商（serveo.net）的服务器转发**——TLS 在它那里解密，
  所以严格来说它在传输途中能看到内容。学校内部使用、且更在意画面不外流的话，
  建议用局域网或电脑本机签到。
- **数据库没有加密**（这是有意为之）：特征向量还原不出人脸，加密的主要收益是防「整个库文件被拷走」，
  而库就在你这台电脑上、有开机密码保护。真正要做的是：**别把 `data/` 目录放进云同步盘**
  （网盘、OneDrive 之类），这是最现实的风险点。备份也请用 U 盘，别走公网。

## 使用流程

1. **新增学生**：进入「学生管理」→「＋ 新增学生」，填写姓名、学号、班级。
2. **注册人脸**：在学生列表点「注册人脸」，正对摄像头，点击「拍摄并注册」。建议每人在不同光线/角度下注册 2–3 张。
3. **创建课程**：进入「课程管理」→「＋ 新增课程」，填写课程名与班级（与学生的班级一致）。
4. **实时签到**：进入「实时签到」→ 选择课程 →「开始签到」，学生依次面对摄像头即自动出勤。
   右下角会显示「最近识别缓存」的状态与自动清空倒计时（必要时可点「立即清空」）。
5. **查看导出**：进入「签到记录」→ 选择课程与日期 →「查询」→「导出 CSV」。

## 常见问题

- **打不开摄像头**：确认浏览器已授权摄像头访问；关闭其他占用摄像头的软件。
- **识别不到/误识别**：保证光线充足、正面朝向镜头；可给同一学生多注册几张照片。
- **提示缺勤但有学生已签到**：确认学生的「班级」与课程的「班级」完全一致。
- **端口被占用**：关闭其他占用 8000 端口的程序，或设置环境变量 `PORT` 换一个端口。
- **手机打不开**：先运行 `allow-phone-access.bat` 放行防火墙；仍不行则可能是 WiFi 开了客户端隔离，需改用隧道方式。
- **签到中途黑屏**：系统会自动重连摄像头（画面左下角那行小字会显示状态），一般几秒内恢复；若提示重连失败，点「结束签到」重新开始即可。
- **人脸数据存储**：系统只保存人脸特征向量（一串数字），不保存原始照片，更利于隐私保护。
- **「最近识别缓存」是什么**：「实时签到」页右下角那行字。它记的是**刚才这几个小时里识别到了谁**
  （只存在内存里，不写硬盘），默认 **2 小时**自动清空，也可以点「立即清空」马上清掉。
  **清它不会影响签到记录，也不会删除学生的人脸** —— 那两样是长期数据，不会自动清。
- **数据备份**：所有数据都在 `data/attendance.db` 这一个文件里，复制走就是完整备份；也可在「签到记录」页导出 CSV。

## 目录结构

```
苍穹签到系统/
├─ CLAUDE.md              # 产品文档与项目约定
├─ README.md              # 本说明
├─ requirements.txt       # Python 依赖
├─ run.py                 # 启动入口（打印本机/手机访问地址）
├─ start.bat              # Windows 启动脚本
├─ start-public.bat       # 公网模式：同时开服务 + HTTPS 隧道（手机可刷脸签到）
├─ start.command          # macOS 启动脚本
├─ allow-phone-access.bat # 放行防火墙，让手机能访问（需管理员）
├─ backend/               # 后端（FastAPI + 识别引擎 + SQLite）
├─ frontend/              # 前端（HTML/CSS/JS，含手机适配）
├─ models/                # 人脸识别模型（ONNX 文件不在仓库里，见 models/README.md）
└─ data/                  # SQLite 数据库（运行时生成，已在 .gitignore 中排除）
```

## 关于本仓库

- `data/`、`output/`、`.venv/`、`.workbuddy/` 均已在 `.gitignore` 中排除。
  其中 `data/attendance.db` 存有学生姓名、学号与人脸特征向量，**不应上传到任何公开位置**。
- 模型文件同理不纳入版本管理，原因见上文「模型文件」一节。
